## 二、核心论点(Thesis)

针对中小企业经营数据长期依赖零散 Excel、存在跨表公式脆弱(`#REF!`/`#DIV/0!`)与重复录入的问题,设计并实现基于 Univer 在线表格与豆包大模型的多业态智能经营系统。核心贡献三条:

1. **「录入与展示分离」架构**(架构脊柱)--PG 唯一事实源,Univer 仅作录入面,从源头消除公式脆弱性与跨表重复录入;
2. **「AI 语义抽取作为唯一入库路径」**(novelty 主脊柱)--以大模型按表头文字语义对齐字段,替代位置式同步,实现抗布局变化、跨业务可复用、确定性可复现的经营数据入库;
3. **完整工程实现与部署验证**--涵盖协同录入(悲观锁)、数据大屏、AI 分析、AI 海报、RBAC 的完整可部署系统,以真实经营数据与部署应用验证。

**适用范围**:中小企业多业态经营数字化;足浴 + 酒店;单编辑者并发财务录入;中文 SME 场景。
**诚实边界**:懒加载水合未接线(不入论点);数据出域至豆包公有云(隐私章节说明);「强智能体」属未来工作(不进核心)。

**[INSIGHT: thesis_statement]** 见上。主脊柱 = (2),架构脊柱 = (1),工程支撑 = (3)。

### 1. 引言(Introduction) — Strong

- **核心论点**:SME 财务数据依赖散乱 Excel/笔记,公式脆弱、跨表重复录入、无法汇总;现有三类做法(电子表格即事实源 / 位置式同步 / 商业协同表格)各有缺陷,**缺少一种既保留表格录入体验、又抗布局变化跨业务复用、且轻量可部署的经营数据入库机制**;本文以 Approach B + AI 语义抽取的完整系统填补。
- **支撑证据**:真实 Excel 含公式错误(coerceMetric 实证拦截 7 天);足浴 16 天真实入库;位置式 sync 三硬伤(spec)。
- **反论**:「AI 降本增效」空泛;overclaim 智能体。
- **回应**:用具体机制(语义抽取替代位置式);智能体划归未来工作。
- **强度**:Strong | **字数**:~800-1000

**[INSIGHT: introduction_summary]** 以 SME Excel 混乱破题;空白 = 缺少低学习成本 + 抗布局变化 + 轻量可部署的入库机制;贡献三条;智能体属未来工作。

### 4. 关键技术(Key Technologies) — Strong(主)/ Weak(酒店)

- **核心论点**:(1) AI 语义抽取作为唯一入库路径--`serializeSheet`/`parseTransposed` 确定性/LLM 回退(`temperature:0`+`json_object`)/`coerceMetric` 双保险/三触发 + SSE + 三层溯源;(2) 工作表级悲观锁--TTL 60s/心跳 5s/单槽接管/两阶段礼让/所有权校验,vs OT;(3) 模板描述符一份五用 + 多业务分派。
- **支撑证据**:`extraction.service.ts`/`lock.service.ts` 代码;足浴 16 天真实入库;`coerceMetric` 拦截实证。
- **反论**:酒店 `layout` 错配致 LLM 超时;LLM 延迟;`temperature:0` 非完全确定性。
- **回应**:酒店降为框架验证;局限诚实;确定性「趋近」非「完全」。
- **强度**:AI 抽取 Strong;锁 Moderate;酒店 Weak | **字数**:~1500-2000(深写)

**[INSIGHT: key_tech_summary]** AI 抽取(主脊柱,确定性 + LLM 回退 + 双保险,真实实证)、悲观锁(单编辑者并发 + 可替换点)、模板分派;局限 = 酒店 layout 错配。
